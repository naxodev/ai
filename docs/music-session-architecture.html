01 / Topology

One provider authority serves many clients

OpenCode and Pi keep their user interfaces local. Their session clients communicate with one daemon for the current user, and that daemon owns the selected macOS media provider.

Machine scopeThe daemon is a same-user, machine-local boundary. It is the current topology, not a proposed deployment mode.

02 / Ownership

Scopes make shutdown ownership explicit

Effect v4 Layers and scopes acquire the provider, coordinator, listener, connections, and finalizers as one daemon graph. Clients own only their connection and presentation lifecycle.

Ownership boundary
Resource Client Daemon Shutdown owner
Session connection and presentation One client, subscriptions, UI, waveform, notifications Accept and fan out frames Host disposal and connection scope
Provider authority NONE Provider Layer, event source, playback clock, poll scheduler Daemon scope
Transport and replay Submit commands and consume replay Global FIFO, status/state refs, revisions Coordinator scope
Artwork OpenCode catalog, download, conversion, cache, rendering; Pi has none Bounded native read and recording-identity validation Respective scoped owner

Shutdown stops or refuses new acceptance, interrupts coordinator work, drains dependent connection children, finalizes provider and event ownership, then closes the listener and removes only its exact proven socket path. Signal, defect, and idle paths converge at that idempotent cleanup boundary.

03 / Protocol and replay

Hello establishes a generation before state becomes authoritative

Owner-only runtime discovery uses startup-marker leases for concurrent first clients, while the hardened socket bind remains the final singleton authority. Twenty concurrent first clients converge on one generation.

hello and replayNegotiate, then project

Hello intersects revision ranges and capabilities. Supported legacy and current clients share a daemon; an incompatible client receives terminal range details and cannot unlink, kill, or replace the healthy generation. Status and state replay immediately after hello.

generation fenceReject stale work

State revisions are monotonic and daemon instance IDs identify generations. A reconnecting client retains its last accepted presentation, adopts only a new hello/replay generation, ignores late old work, and never replays commands.

Command lossAn admitted command without a result at connection loss is indeterminate. Reconnect is for a fresh generation, not a command retry mechanism.

04 / Bounded work

Separate authority lanes protect healthy peers

The daemon contains provider observation, command execution, connection input, state fan-out, and artwork work so one stalled reader or expensive request does not become a global pause.

1

Provider authority

One event stream and one sampling/poll authority.

Provider observation remains O(1). Sampling is serialized and coalesced; recovery polling belongs to the coordinator, not a host.

2

Global transport FIFO

Commands from OpenCode and Pi share one order.

The bounded command queue serializes provider transport. Clients receive correlated required responses rather than inferring an outcome from later state.

3

Per-connection fan-out

Finite inbound and pending work per peer.

State updates coalesce for a slow reader while mandatory responses and status are preserved. A paused or abusive connection can be disconnected locally without blocking 23 healthy peers or terminating the daemon.

4

Native artwork

Bounded and deduplicated by identity.

The daemon validates complete recording identity before and after the read, bounds payload/cache work, and shares concurrent identical requests. Artwork failure does not block playback state.

05 / Lifecycle

The last client starts an idle grace, not an immediate teardown

A completed new connection cancels the zero-client grace. If grace expires, the daemon follows the same scoped shutdown path; a later client can start or adopt a new generation.

Startup

An exact-owner marker lease coordinates launch attempts. The daemon starts detached, and socket binding decides the one winner.

Reconnect

Schedule-paced attempts retain accepted presentation state until a handshaken replacement replays.

Idle

Only negotiated client departure starts the bounded grace. Joining cancels it.

Cleanup

Finalizers remove only artifacts whose identity and ownership were proven; they do not delete a replacement path.

06 / Host boundaries

Presentation remains host-local

OpenCode music player

One reconnecting client feeds compact and sidebar Solid UI. OpenCode owns optimistic presentation, seek coalescing, notifications, waveform projection, iTunes lookup and image conversion, bounded cache/jobs, Kitty graphics, and half-block fallback rendering.

Pi music dock

One live TUI session owns one reconnecting client, a composable status line, waveform, notifications, commands, and shortcuts. Pi does not request or render artwork.

Neither host owns provider discovery, provider polling, the playback clock, native media reads, or cross-host transport ordering. Disposing one client leaves the daemon available to every other client.

08 / Failure behavior

Contain local failure without replacing healthy authority

Incompatible client

Return actionable revision-range details and leave the healthy daemon untouched.

Slow reader

Apply bounded per-connection work and disconnect locally when required.

Provider failure

Publish status and recover through the daemon-owned event and polling paths.

Artwork failure

Return an artwork outcome while preserving playback-state delivery.

Host reload

Dispose one client and local presentation; remaining clients keep the daemon generation alive.

Final disconnect

Allow bounded idle expiry to close the graph and clean exact owned runtime artifacts.

  • One same-user daemon owns one provider authority.
  • Hello and replay establish compatible generations.
  • Revisions and instance IDs fence stale state.
  • Commands never replay after connection loss.
  • Global FIFO ordering spans OpenCode and Pi clients.
  • Bounded local failures do not block healthy peers.
  • Native artwork reads validate identity and remain bounded.
  • Presentation and OpenCode catalog work stay host-local.
