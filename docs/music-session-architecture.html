Field guide 01 / macOS Now Playing

Music session architecture

How OpenCode and Pi plugin instances observe one machine-local media session, isolate their work, reject stale results, and scale toward a broker only when coordination is required.

01 / Mental model

Follow state from provider to pixels

The macOS provider is the authority. The shared core normalizes its output and maintains a backend-local playback clock. Each host controller schedules work and protects its lifecycle. The host UI performs the final presentation.

Boundary The core generates waveform levels; it does not analyze audio. Registration, lifecycle, notifications, controls, and rendering remain host responsibilities.

02 / Ownership

Every host instance owns a complete runtime

Treat an OpenCode controller or a live Pi session as the ownership boundary. Nothing in the current architecture coordinates those owners across processes.

03 / Provider events

A snapshot is data; invalidation is a prompt

media-control stream --no-diff --no-artwork emits complete payloads. The core validates and normalizes complete payloads before exposing them. Partial or malformed stream lines do not become snapshots.

event.type = snapshot Project immediately

The state is authoritative. OpenCode replaces player state. Pi projects with its authoritative path. Both invalidate older sample requests so a slower provider read cannot restore stale state.

NOT THE SAME
reason = stream-terminated Request recovery

The event carries no replacement player state. The host requests player(). The core disposes the ended stream and independently schedules its restart.

Fallback nowplaying-cli has no subscription. The same bounded host poll is therefore its only provider-update path.

04 / Concurrency

Keep four work lanes independent

A slow provider read must not block a transport command. Artwork must not delay state projection. The implementations enforce those properties with separate lanes rather than one shared promise chain.

1

Synchronous UI projection

Latest accepted state reaches the host immediately.

snapshot→state→render

Authoritative snapshots do not wait behind sampling, transport, or artwork. Optimistic transport state also projects after a successful command while a short reconciliation is scheduled.

2

Coalesced sampling

At most one provider read runs per host instance.

request A→in flight+B/C = pending→one follow-up

Requests during an active sample set one pending flag. The drain performs one follow-up using the newest request sequence, instead of starting parallel reads or preserving every trigger.

3

FIFO transport

One command runs at a time inside one instance.

play→next→pause→reconcile

Pi preserves every play, pause, next, and previous intent. OpenCode does the same and also supports seek. Adjacent pending OpenCode seeks collapse to the newest target while all callers still settle.

4

Keyed artwork enrichment

OpenCode-only work keyed by recording metadata.

track key→native / search→completion event

Concurrent interest in one key shares a job. Completion publishes the identity with the result, so presentation merges it only into the matching track. Failed resolution uses bounded attempts and delayed retries without blocking playback state.

05 / Stale work

Prove a result is still eligible

Async completion alone does not authorize a state update. Each lane checks the current owner and the revisions that can make its result obsolete.

Lifecycle guard

OpenCode captures a lifecycle generation around sampling and transport work. Pi checks that the live-session object is still active and still equals the extension's current session.

Sample sequence guard

Every refresh request advances a sequence. An authoritative snapshot advances it again. A read projects only if its captured sequence remains current.

Transport revision guard

Successful commands advance a revision. A sample started before that command cannot overwrite the command's optimistic state or a later reconciliation.

Stream generation guard

The core assigns each stream attempt a generation. Termination or disposal invalidates the generation, suppressing late lines, duplicate terminal callbacks, invalidations, and restarts.

Bounded recovery timing

Host polling remains active even with a stream. It recovers missed state and supports the polling-only fallback. Stream restart backoff resets to one second after a valid snapshot.

06 / Host comparison

Share mechanics; preserve host presentation

Both hosts consume the same normalized provider contract, playback clock, commands, reconciliation, formatting, and waveform engine. Their user-interface responsibilities intentionally differ.

OpenCode music player

Registers global commands and app/sidebar slots. Projects state into a Solid compact bar and sidebar. Supports seek, optimistic progress, notifications, artwork enrichment, Kitty graphics, and half-block fallback rendering. It preserves artwork presentation across ordinary sampled-state merges.

Pi music dock

Registers slash commands and shortcuts. Publishes one composable status through ctx.ui.setStatus. Renders an ANSI waveform and clipped metadata. It does not own Pi's footer and does not fetch or cache artwork. Its controls omit seek.

07 / Multi-instance reality

Isolation is local; convergence is global

Separate OpenCode and Pi processes do not share JavaScript memory, queues, clocks, timers, stream processes, or caches. They do share the same macOS Now Playing authority through independent provider calls.

What scales with instances

With media-control, each of the N host instances owns a stream process and recovery poll. Each of the O OpenCode instances also has process-local artwork work and a cache of at most 32 settled entries.

What does not coordinate

FIFO ordering stops at a process boundary. There is no global command queue, lock, or winner. Two instances can issue commands concurrently, and the provider decides the observed outcome.

How instances converge

A command affects machine-local media state. Later authoritative stream snapshots or bounded polls carry that resulting state back to every healthy instance. Convergence is eventual, not a global transaction.

Fallback behavior

nowplaying-cli remains polling-only. Under that backend there are no provider stream processes, but each instance still owns its 3/5/8-second polling cycle and backend clock.

08 / Scale path

Add one broker per Mac, not per fleet

09 / Operations

Design and operate against invariants

Failures should reduce freshness or presentation quality without allowing stale work to regain authority or leaving background work alive after its host disappears.

Provider stream exits

Emit one invalidation, request a recovery sample, dispose the old stream, and retry after 1/2/4/8 seconds. Continue bounded host polling while recovery proceeds.

Provider read fails

Pi keeps its accepted state and waits for a later poll. OpenCode may expose the error unless a transport error has priority. The next bounded poll remains scheduled.

Transport fails

Notify in the host and keep advancing the local FIFO so one rejected command does not strand following intents. OpenCode requests immediate reconciliation; Pi recovers on its next bounded poll.

Artwork fails

Playback state stays usable. OpenCode publishes a null completion, retries the keyed entry with delay for at most three attempts, and preserves identity checks at merge time.

Host reloads or exits

Mark the owner dead first. Then release subscriptions, timers, waveform work, UI registrations, and pending waiters. Late async results must observe the dead lifecycle and become no-ops.

Clients disagree temporarily

Do not infer a distributed lock. Accept temporary divergence and converge from later authoritative provider snapshots. Add a local broker only when cross-client ordering is a real requirement.

  • One backend owns one playback clock; no instance mutates another instance's clock.
  • A complete stream snapshot projects directly and invalidates older reads.
  • A stream invalidation requests data; it never masquerades as player state.
  • Sampling remains single-flight and coalesces repeated triggers into one follow-up.
  • Transport remains FIFO per owner; adjacent pending seeks coalesce only in OpenCode.
  • Provider reads, transport commands, and artwork jobs never share a blocking lane.
  • Every async projection checks lifecycle plus the relevant sequence or revision.
  • Disposal is idempotent and suppresses late lines, callbacks, updates, and restarts.
  • Poll delays stay bounded at 3/5/8 seconds; stream restart stays capped at 8 seconds.
  • A future broker keeps client presentation and lifecycle local to each host.
  • Cross-process command order does not exist until a machine-local global queue owns it.
  • One Mac needs one broker because another machine cannot observe its media session automatically.
